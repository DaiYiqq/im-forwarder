# 告知—同意流程（PIPL 第二十三条 / 第三十九条）

对应源码：`src/compliance/consent.ts`、`consent-store.ts`、`src/pipeline/forward.ts`、`src/pipeline/notify.ts`。
适用场景：路由声明 `contentOwner: third-party`（转发**他人**聊天内容），或境外链路需要第 39 条单独同意。

---

## 1. 状态机

```
                    ┌──────────────────────────────────────────┐
                    │ 状态 0：未同意                            │
                    │ 收到他人消息 → 不转发，发《转发告知》     │
                    └───────────────┬──────────────────────────┘
                                    │ 对方回复「同意转发」
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │ 状态 1：已同意境内转发                    │
                    │ 后续消息正常转发                          │
                    └───────────────┬──────────────────────────┘
                                    │ 若目标含 Telegram：
                                    │ 还需「同意出境」
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │ 状态 2：已单独同意出境                    │
                    │ 后续消息可转发至境外接收方                │
                    └───────────────┬──────────────────────────┘
                                    │ 对方回复「撤回同意」
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │ 状态 0（记录被删除）                      │
                    └──────────────────────────────────────────┘
```

要点：

- **默认拒绝**：没有有效同意 → 一条都不转发；
- **两次独立同意**：境内转发同意 ≠ 出境同意，不能互相替代；
- **顺序强制**：未取得境内同意时，回复「同意出境」会被提示"先回复同意转发"；
- **指令不转发**：同意/撤回关键词这条消息本身**不会**被转给目标，避免污染对话。

## 2. 真实对话示例

```
（微信私聊，对方 = wxid_colleague，目标 = QQ 10002）

对方：晚上七点老地方见

[不转发]  本服务 → 对方：
  【转发告知 · 需你同意】
  你发送的消息默认不会转发。若你同意，本工具会把你的文本消息转发给以下接收方：
    1) 接收方：你的 QQ 小号
       联系方式：QQ 10002 / you@example.com
       处理目的：个人自用消息同步，无商业用途
       处理方式：通过 EasyBot 网关以文本消息发送
       信息种类：文本消息内容、发送者平台标识、发送时间
       保存期限：不保存正文；仅内存转发，日志不含内容

  本工具只转发文本；不保存消息正文，不记录到日志；转发后你随时可以撤回同意。
  如果你同意，请回复「同意转发」（需单独一条消息，且仅本会话生效）。
  随时可回复「撤回同意」撤回，撤回后本会话不再转发。
  （告知版本：2026-10-18.v1）

对方：同意转发

[不转发该指令]  本服务 → 对方：
  已记录你的「同意转发」。之后本会话的文本消息将被转发；回复「撤回同意」可随时停止。

对方：明天几点？

[转发]  → QQ 10002：明天几点？

对方：撤回同意

[不转发]  本服务 → 对方：
  已撤回同意，本会话后续消息不再转发。已经转发出去的消息无法追回。
```

若该链路同时在境外：

```
本服务 → 对方：
  【数据出境告知 · 需你单独同意】
  上述接收方中有一方位于境外（Telegram，服务器在境外）。
  向境外提供你的个人信息可能构成《个人信息保护法》第三十八条所称的出境行为。
  境外接收方信息与处理说明：
    1) 接收方：你的 Telegram 机器人
       联系方式：@your_bot
       处理目的：个人自用跨平台同步
       处理方式：通过 Telegram Bot API 以文本消息发送
       信息种类：文本消息内容、发送时间
       保存期限：不保存正文

  出境后，你依据《个人信息保护法》第四章享有的权利（查阅、复制、更正、删除、转移等）
  可能难以向境外接收方直接行使。本工具不代为完成第三十八条要求的安全评估/标准合同/保护认证。
  如果你已被告知上述风险并单独同意出境，请回复「同意出境」（与上一步的同意是两次独立的同意）。
  随时可回复「撤回同意」撤回全部同意。
```

## 3. 关键词与配置

```yaml
compliance:
  thirdPartyConsent:
    enabled: true
    noticeVersion: "2026-10-18.v1"     # 文案变更后，旧的同意自动失效
    persist: true                       # 落盘为 data/consent.json（仅元数据）
    allowCrossBorder: false             # 默认禁止"他人内容 + 出境"组合
    consentKeywords: ["同意转发"]
    crossBorderKeywords: ["同意出境"]
    revokeKeywords: ["撤回同意"]
    noticeCooldownMs: 600000            # 告知回执冷却 10 分钟，防刷屏
    ttlDays: 30                         # 同意有效期
```

**匹配规则**：整条消息精确匹配（去空白、去常见中英文标点、转小写）。
不是"包含"匹配 —— 否则对方在正常聊天里引用到"同意转发"四个字就会误授权。

**粒度**：同意按**链路（路由）**累计。同一会话若配置了多条 `contentOwner: third-party`
路由（例如同时转发到 QQ 与 Telegram），每条路由需要各自确认 —— 因为每次告知只会列出
该路由的目标接收方，不能让一次同意覆盖未逐条告知的其它接收方。
`data/consent.json` 的 `grants[scope].routes[]` 记录了这个范围；旧版记录没有该字段时
按"该会话全部他人内容路由"解释（建议清空后重新走流程）。

## 4. 存储格式与内容边界

文件：`data/consent.json`（`persist: true` 时；受 `.gitignore` 保护）

```json
{
  "version": 1,
  "records": {
    "wechat:wxid_colleague": {
      "scopeKey": "wechat:wxid_colleague",
      "platform": "wechat",
      "conversationId": "wxid_colleague",
      "grants": {
        "domestic": {
          "noticeVersion": "2026-10-18.v1",
          "grantedAt": "2026-10-18T12:00:00.000Z",
          "expiresAt": "2026-11-17T12:00:00.000Z",
          "routes": ["colleague-wx-to-qq"]
        }
      },
      "updatedAt": "2026-10-18T12:00:00.000Z"
    }
  }
}
```

**有**：会话标识、同意范围、告知版本、时间戳。
**没有**：消息正文、消息 ID、转发内容、聊天记录、发送频率统计。

写入采用"临时文件 + rename"原子替换；文件损坏时**拒绝启动**（`CONSENT_STORE_CORRUPT`），
不允许在"不知道谁同意过"的状态下运行。

## 5. 撤回与删除

| 操作 | 效果 |
|---|---|
| 对方回复「撤回同意」 | 删除该会话全部授权记录，后续不再转发 |
| 删除 `data/consent.json` | 清空所有同意（等价于全部撤回）；重启生效 |
| `ttlDays` 到期 | 记录自动失效（判定时检查 `expiresAt`） |
| 提升 `noticeVersion` | 所有旧同意失效，需要重新告知并重新取得同意 |

> 撤回**不能**追回已经发送到对方平台的消息副本 —— 告知文案里已如实写明，不粉饰。

## 6. 能力边界（务必阅读）

| 局限 | 后果 |
|---|---|
| 无法验证回复者身份 | 只能证明"该会话的回复方声称同意"；账号被他人使用时结论不可靠 |
| 无法覆盖群成员 | 所以本项目**整体不支持群聊**（不是"暂未实现"） |
| 无法验证接收方实际处理行为 | 只能要求配置里填写真实信息 |
| 无法阻止对方误点 | 关键词精确匹配降低误触，但无法杜绝 |
| 告知可能被忽略 | 对方不回复 = 永不转发（默认安全方向） |

**为什么不用配置里的 `iAgree: true`？** 那只是使用者对自己的承诺，不是数据主体的同意。
第 23 条要求"取得个人的单独同意"，必须由本人作出。本项目只在"出境 + 本人消息"场景使用配置确认，
因为此时数据主体就是使用者本人。

## 7. 本地验证流程（不需要真实平台）

```powershell
# 终端 A：启动 mock 网关
npm run mock

# 终端 B：用 mock 地址 + 开启同意机制 + 一条 third-party 路由的配置启动
npx tsx src/main.ts --config <你的-third-party-配置>.yaml

# 在 mock 的控制台/测试里 emit 一条他人消息 → 观察：只给源会话发告知，目标会话零发送
# emit 一条文本为「同意转发」的消息 → 观察：consent.json 出现记录，指令未被转发
# 再 emit 普通消息 → 观察：mock.sent 出现目标会话的转发请求
```
